# Установка excel-key-cleaner — инструкция для ИИ-агента (Claude, Codex, любой другой)

Это письмо адресовано ИИ-агенту на компьютере получателя. Человек прислал архив
`excel-key-cleaner.zip`, файл `excel-key-cleaner.xlam` или ссылку на репозиторий и попросил
установить. Инструкция для человека — `INSTALL.md` рядом; здесь то же, но с тем, что агенту
важно знать и чего ему делать нельзя.

## Что это

Надстройка Excel: в выделенных ячейках меняет кириллические буквы, набранные вместо латинских
(`А В Е К М Н О Р С Т Х а е о р с х`), переносы строк, невидимые символы и лишние пробелы. Точка
входа одна — `Sub CleanKeys()` в модуле `Cleaning`; перед работой она показывает форму
`CleaningForm` с пятью флажками. Нужен Excel 2016+ на Windows; `Declare`-вызовов нет, разрядность
Office роли не играет.

| Файл | Что это |
|---|---|
| `excel-key-cleaner.xlam` | надстройка: модули `Cleaning`, `CleaningForm`, `Ribbon` + лента (вкладка «Очистка ключей», пункт «Очистить ключи» в меню правой кнопки по ячейке) |
| `Cleaning.bas`, `CleaningForm.frm` + `.frx` | те же модули для установки в `PERSONAL.XLSB` (способ 2); `.frx` — бинарная часть формы, лежит рядом с `.frm`, отдельно не импортируется |

Поведение, которое стоит знать, прежде чем что-то «чинить» (подробно — README и CHANGELOG):
- работает **только по выделению**; обрабатывает **все текстовые ячейки выделения**, включая
  скрытые строки и ячейки с разным оформлением символов (оформление сохраняется); формулы, числа,
  даты, ошибки и пустые не трогает, но считает в отчёте; всё нетронутое **называет по адресу и
  выделяет на листе** — это требование владельца, не опция;
- кириллица меняется **по словам**: слово меняется, если «похоже на код» оно само или вся ячейка;
  русское слово (только кириллица, есть строчная буква) не меняется никогда; `У/у` не заменяется
  намеренно;
- текст остаётся текстом (`00123`, `12/03`, `=1+1` не превращаются в число, дату, формулу);
  план считается до первой записи, ошибка при записи — откат.

## Способ 1 — надстройка (основной)

1. **Разблокировать файл.** Файл из интернета помечен Windows, и Excel не запустит из него макросы.
   Человек делает это сам: правая кнопка → Свойства → «Разблокировать». Агент может предложить
   `Unblock-File <путь>` — но только с явного согласия человека: это решение о доверии файлу.
2. **Скопировать** в `%APPDATA%\Microsoft\AddIns\` (стандартная папка надстроек пользователя; по
   умолчанию она НЕ надёжное расположение — поэтому шаг 1 обязателен).
3. **Включить.** Проще всего руками: `Файл → Параметры → Надстройки → Надстройки Excel → Перейти…`
   → галочка «Очистка ключей». Через COM (если человек согласен, что агент меняет список
   надстроек Excel; все Excel перед этим закрыть). Этот фрагмент на стенде проекта не запускался —
   он меняет настройки Excel того, кто его запускает; проверь результат глазами человека:
   ```powershell
   $excel = New-Object -ComObject Excel.Application
   try {
       $wb = $excel.Workbooks.Add()                 # пустая книга на всякий случай: через COM AddIns.Add без открытой книги, по сообщениям, падает (документация этого не требует)
       $ai = $excel.AddIns.Add("$env:APPDATA\Microsoft\AddIns\excel-key-cleaner.xlam")
       $ai.Installed = $true
       "OK: $($ai.Title) installed=$($ai.Installed)"
       $wb.Close($false)
   } finally { $excel.Quit() }
   ```
4. **Проверить:** человек открывает Excel — вкладка «Очистка ключей» после «Главной».

Не добавляй надёжные расположения и не меняй параметры макросов сам — это настройки безопасности
человека; `INSTALL.md` объясняет ему, как и зачем.

Если раньше макрос стоял модулем в `PERSONAL.XLSB`, надстройка работает рядом с ним, но старую
копию лучше удалить (спроси человека): она остаётся в `Alt+F8` и может отставать по версии.

## Способ 2 — модули в `PERSONAL.XLSB`

Нужен включённый «Доверять доступ к объектной модели проектов VBA»
(`(Get-ItemProperty "HKCU:\Software\Microsoft\Office\16.0\Excel\Security").AccessVBOM` = `1`).
Если выключен — **попроси человека** включить галочку сам или поставить вручную (`INSTALL.md`,
способ 2): агент этот параметр не меняет.

Все Excel закрыть, затем (пути подставь свои):
```powershell
$personalPath = "$env:APPDATA\Microsoft\Excel\XLSTART\PERSONAL.XLSB"
$srcDir       = "<папка, куда распакован архив>"
$excel = New-Object -ComObject Excel.Application
$excel.Visible = $false; $excel.DisplayAlerts = $false
try {
    $wb = $excel.Workbooks.Open($personalPath)
    if ($wb.ReadOnly) { throw "PERSONAL.XLSB открыт в другом Excel - сначала закрыть" }
    foreach ($name in @('Cleaning','CleaningForm')) {
        foreach ($c in @($wb.VBProject.VBComponents)) { if ($c.Name -eq $name) { $wb.VBProject.VBComponents.Remove($c) } }
    }
    [void]$wb.VBProject.VBComponents.Import((Join-Path $srcDir "Cleaning.bas"))
    [void]$wb.VBProject.VBComponents.Import((Join-Path $srcDir "CleaningForm.frm"))
    $wb.Save()
    "OK: Cleaning + CleaningForm -> $personalPath"
} finally {
    if ($wb) { $wb.Close($false) }
    $excel.Quit()
}
```
Если `PERSONAL.XLSB` нет — человек создаёт её записью любого макроса в «Личную книгу макросов»
(`INSTALL.md`, способ 2, шаг 2). Запуск: выделить ячейки → `Alt+F8` → `CleanKeys`.

## Грабли, на которые уже наступали

- `Application.Run "Модуль.Макрос"` без имени книги ищет макрос в **активной** книге; если активна
  другая — «Не удается выполнить макрос». Вызывай с полным именем: `'Книга1'!Cleaning.CleanKeys`.
  Тот же текст ошибки даёт модуль, который не компилируется.
- Импортировать в Excel надо файлы из архива или `dist/` (cp1251). `src/` в репозитории — UTF-8
  для чтения на GitHub; импорт оттуда портит кириллицу.
- Макрос показывает форму и `MsgBox` — запуск без человека повиснет на них. Для проверок есть стенд
  в репозитории (`tests/`), он подменяет форму и `MsgBox`; сам макрос в чужой книге человека без
  его ведома не запускай.
