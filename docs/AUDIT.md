# Аудит версии 1.0 — что было найдено и как проверялось

Дата: 2026-09-21. Excel 2024 x64, Windows 11 ru-RU. Два независимых ревью (Claude Code и
OpenAI Codex) плюс стенд из `tests/`, прогнанный на **настоящем** коде v1: 120 прогонов (20
входных строк × 6 наборов флажков) сверены с эталонной моделью — совпадение 120/120, то есть
всё ниже — свойства логики, а не случайности; и 16 проб на то, что строкой не выражается.

Вердикт был: в таком виде отдавать другим людям нельзя. Все пункты закрыты в 2.0–2.2
(см. `CHANGELOG.md`), стенд после переписывания — 186/186 и 18 чистых проб.

## Подтверждённые дефекты v1 (по тяжести)

### 1. `cell.Value = textValue` перепарсивает текст — в числа, даты и формулы
Ячейка формата «Общий» с текстом (так выглядит любой столбец, загруженный Power Query) после
очистки записывается обратно как строка, и Excel разбирает её заново по правилам **en-US**
(это VBA, не локаль пользователя). Стенд, действие «удалить пробелы»:

| было (текст) | стало | тип |
|---|---|---|
| `00123 ` | `123` | число — ведущие нули потеряны |
| `1.2 ` | `1,2` | число |
| `1E5 ` | `100000` | число |
| `12/03 ` | `03.дек` | дата |
| `10-12 ` | `12.окт` | дата |
| `TRUE ` | `ИСТИНА` | логическое |
| `(5) ` | `-5` | число |
| `=1 +  1` (текст) | **формула `=1 + 1`, значение `2`** | формула |

Последняя строка — инъекция формулы из импортированного текста.
**Исправление:** запись через формат `@` с возвратом прежнего формата (`PutText`); проверено на
тех же входах — все остались текстом.

### 2. `#Н/Д` в выделении роняет макрос посреди диапазона
`If cell.HasFormula = False And cell.Value <> ""` — VBA вычисляет обе части `And`; `cell.Value`
на ошибке даёт `Type mismatch`. Ячейки до неё уже перезаписаны, отката нет (VBA стирает Undo),
`Application.ScreenUpdating` остаётся `False`.
**Исправление:** отбор только текстовых констант через `SpecialCells`; план до первой записи;
откат; восстановление состояния приложения.

### 3. Крестик формы = «выполнить с настройками по умолчанию»
Нет `UserForm_QueryClose`. Закрытие крестиком выгружает форму; следующее обращение к ней в
макросе молча создаёт **новый** экземпляр с пустым `Tag` и флажками по умолчанию.
Стенд: `after Unload: Tag=[] CheckBox1=True CheckBox2=True CheckBox4=True`.
**Исправление:** продолжение только при `Tag = "OK"`, который ставит одна кнопка «Выполнить».

### 4. Замена кириллицы уродует обычный русский текст
`ВЕТЕР → BETEP`, `ХОРОШО → XOPOШO`, `СМР работы → CMP работы`.
**Исправление:** замена только в строках, похожих на код (есть латинская буква, вся
кириллица — из списка омоглифов); остальное считается и показывается в отчёте.

### 5. Реальная дата-время под «удалить пробелы» становится текстом
`CStr(дата)` = `21.09.2026 12:00:00` → пробел удалён → записано обратно как текст
`21.09.202612:00:00`. **Исправление:** нетекстовые ячейки не обрабатываются.

### 6. `Ctrl+A` → `Overflow`; целый столбец — 8 секунд впустую
`Selection.Count` — `Long`, весь лист не помещается. Один столбец — перебор 1 048 576 ячеек,
измерено 8,3 с. **Исправление:** `SpecialCells` + `CountLarge`; целый столбец — 0,0 с.

### 7. Строка максимальной длины → `Overflow`
`Dim i As Integer` при пределе ячейки 32 767 = пределу `Integer`. **Исправление:** `Long`.

### 8. Защищённый лист → ошибка 1004 посреди цикла
**Исправление:** проверка `ProtectContents And Locked` для каждой изменяемой ячейки до первой
записи; отказ с указанием адреса.

### 9. Rich text сводится к формату первого символа
**Исправление:** такие ячейки пропускаются (`IsNull` на свойствах `Font`) и считаются.

### 10. Статистика врёт
`A↵B → A B`, отчёт: «Удалено переносов: 0 … Изменений не найдено» — счётчик считал разницу
длин, а замена переноса на пробел длину не меняет. **Исправление:** события считаются по исходной
строке, отдельный счётчик изменённых ячеек.

### 11. Чего действия не видели
Неразрывный пробел, табуляция, символы нулевой ширины, строчная кириллица; нормализация не
обрезала края. Всё закрыто в 2.0/2.1.

### 12. Косметика
`?` вместо галочек в подписях (символы потерялись при сохранении исходника в cp1251); нет
`Default`/`Cancel` у кнопок. Закрыто; с формы спецсимволы убраны вовсе.

## Расхождения между двумя ревью, решённые стендом

| Утверждение | Итог |
|---|---|
| инъекция формулы из текста `=1 + 1` | подтверждено прогоном |
| дата-время под действием 3 теряет тип | подтверждено |
| крестик формы запускает обработку | подтверждено |
| «целый столбец надолго заблокирует Excel» | частично: 8,3 с на столбец, не зависание |
| фикс записи через формат `@` | проверен до применения: `00123`, `1.2`, `1E5`, `12/03`, `=1 + 1`, `TRUE` остались текстом при возвращённом «Общем» |

## Второй круг: замечания к переписанной версии

Коллеги (v2 → v2.1): `У→Y` вернулась вопреки решению владельца — убрана; символы нулевой ширины
и редкие пробелы не чистились — возвращены; глифы `✓`/`→` на форме — убраны (MSForms не
подставляет глифы из других шрифтов); строка целиком в русской раскладке не чинится — принято
как цена защиты русских слов.

Codex (v2.1 → v2.2): обработчик ошибок включался после выключения `ScreenUpdating`/`EnableEvents`;
`IsRichText` не видел `Superscript`/`Subscript`; правило «есть латиница» пропускало `МОСТ-A` →
`MOCT-A`; откат не покрывал ячейку, на которой упала запись. Все четыре исправлены и покрыты
стендом. Пятое — обход предела в 8192 области у `SpecialCells` — отклонено измерением на
целевом Excel (10 000 областей возвращаются верно); в README добавлено требование Excel 2010+.

## Что проверено и в порядке уже в v1
Разрывное выделение обрабатывается во всех областях; объединённые ячейки — верхняя левая, без
ошибок; формулы с обычным значением не переписываются; числа и даты без пробелов не трогаются;
флажки 3 и 4 взаимоисключающие.

## Ловушки среды, найденные по дороге (полезны любому, кто гоняет Excel через COM из PowerShell)
- Через PowerShell COM `Range.NumberFormat` ведёт себя как `NumberFormatLocal`: `"General"`
  бросает ошибку, читается `Основной`. Из VBA то же свойство читает и принимает `General`.
- Адрес из нескольких областей через COM на ru-RU: `Range("B2:B3;D2:D3")` — разделитель `;`.
- `SpecialCells` на диапазоне из одной ячейки молча расширяется на весь лист.
- Массив-параметры (`[string[]]`) не переживают вызов `powershell -File`; передавайте одну
  строку с разделителем.
