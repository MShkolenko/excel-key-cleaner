# excel-key-cleaner — очистка ключей в Excel

[![Версия](https://img.shields.io/github/v/release/MShkolenko/excel-key-cleaner?label=%D0%B2%D0%B5%D1%80%D1%81%D0%B8%D1%8F)](https://github.com/MShkolenko/excel-key-cleaner/releases/latest)
[![Лицензия MIT](https://img.shields.io/github/license/MShkolenko/excel-key-cleaner?label=%D0%BB%D0%B8%D1%86%D0%B5%D0%BD%D0%B7%D0%B8%D1%8F)](LICENSE)
[![Excel 2016+ · Windows](https://img.shields.io/badge/Excel-2016%2B%20%C2%B7%20Windows-217346?logo=microsoftexcel&logoColor=white)](docs/INSTALL.md)

Надстройка для Excel: в выделенных ячейках исправляет кириллические буквы, набранные в кодах вместо
похожих латинских (`10UРH` → `10URH`), и убирает переносы строк, невидимые символы и лишние
пробелы. Сделана для таблиц, где ключи оборудования и работ переносят между системами руками, а
потом они не сходятся в `ВПР` и Power Query, потому что «одинаковые» строки различаются одной
русской буквой или неразрывным пробелом.

![Вкладка «Очистка ключей» на ленте Excel](docs/ribbon.png)

## Установка — 5 минут

Нужен Excel 2016 или новее на Windows. Больше ничего.

1. Скачайте `excel-key-cleaner.xlam` со [страницы релизов](https://github.com/MShkolenko/excel-key-cleaner/releases/latest).
2. Правая кнопка на файле → «Свойства» → **«Разблокировать»** → ОК. Иначе Excel заблокирует
   макросы файла, скачанного из интернета.
3. Положите файл в папку `%APPDATA%\Microsoft\AddIns` (вставьте это в адресную строку Проводника).
4. Excel → `Файл → Параметры → Надстройки` → внизу «Управление: Надстройки Excel» → «Перейти…» →
   галочка **«Очистка ключей»** → ОК. Появится вкладка «Очистка ключей».

**Обновить:** закройте Excel, замените файл в той же папке новым (и снова «Разблокировать»).

Подробно, с разбором типичных ошибок, надёжными расположениями и установкой без надстройки
(модулями в `PERSONAL.XLSB`) — [`docs/INSTALL.md`](docs/INSTALL.md).

## Как пользоваться

1. Выделите ячейки — столбец, диапазон или несколько областей через `Ctrl`. Макрос работает только
   с выделением: что не выделено, не тронет.
2. Вкладка **«Очистка ключей» → «Очистить ключи»** — или правая кнопка по выделению → «Очистить ключи».
3. Отметьте, что сделать, и нажмите **«Выполнить»** (или `Enter`). «Отмена», `Esc` и крестик
   ничего не меняют.

| Флажок | Что делает | Пример |
|---|---|---|
| 1. Кириллица → латиница | Меняет русские буквы, похожие на латинские, там, где это код. Русские слова не трогает | `10UРH` → `10URH`<br>`Опора XX.0120.10UМА` → `Опора XX.0120.10UMA`<br>`Насос XX.0120.10UMA` — без изменений |
| 2. Переносы строк → пробел | Перенос строки внутри ячейки становится пробелом | `ABC`⏎`001` → `ABC 001` |
| 3. Удалить все пробелы | Убирает все пробелы, включая неразрывные, табуляцию и невидимые символы | `XX U1 ABC` → `XXU1ABC` |
| 4. Нормализация пробелов | Несколько пробелов подряд — один; неразрывный и прочие — обычный пробел; невидимые удаляются | `XX   U1` (три пробела) → `XX U1` |
| 5. В выделении только коды | Кириллица меняется везде, без проверки «похоже на код». Включайте, только если в выделении одни ключи | `СЕ.U1` → `CE.U1` |

По умолчанию включены 1, 2 и 4. Пункты 3 и 4 вместе нельзя. **Пробелы и невидимые символы по краям
ячейки убираются всегда**, при любых флажках и даже без единого флажка.

**Отчёт** после прогона: сколько ячеек просмотрено и изменено, сколько не тронуто и почему. Адресов
в нём нет — то, на что стоит посмотреть, **выделено на листе**:

| Строка отчёта | Что значит |
|---|---|
| «ЛАТИНИЦА И КИРИЛЛИЦА В ОДНОМ СЛОВЕ: N яч.» | Похоже на код, за который правило не взялось (`СЕ.U1`, `Cекция`). Ячейки выделены — проверьте глазами; если это коды, повторите на том же выделении с флажком 5 |
| «Русский текст оставлен как есть: N яч.» | Так и должно быть. Не выделяется |
| «НЕ ТРОНУТО … заголовков таблиц Excel» / «… объединённых яч., выделенных не целиком» | Выделены. Заголовки переименуйте вручную; объединённую область выделите целиком |
| «ЗАПИСАНЫ ЦЕЛИКОМ … яч. с оформлением символов» | Ячейка с разным оформлением букв записана целиком (обычно текст длиннее 255 символов): оформление могло съехать. Выделены — посмотрите |

## Что макрос не трогает

- **Ничего за пределами выделения.** Целый столбец или `Ctrl+A` — тоже выделение, пустая часть
  просто отбрасывается.
- **Формулы, числа, даты, логические значения, ошибки (`#Н/Д`) и пустые ячейки** — считает в
  отчёте, но не меняет.
- **Русские слова.** И `У/у` не меняет никогда: русская «у» и латинская «Y» — разные буквы.
- **Не транслитерирует:** `Ж` не станет `Zh`, `П` не станет `P`. Это исправление опечаток
  раскладки, а не перевод в латиницу.
- **Не угадывает:** кириллическая `О` не станет нулём, `З` — тройкой; без знания структуры ключа
  это было бы угадыванием.
- **Текст остаётся текстом:** `00123` не станет числом `123`, `12/03` — датой, `1E5` — `100000`,
  `=1 + 1` — формулой.

## Подробно: правило замены кириллицы

- **Какие буквы:** `А В Е К М Н О Р С Т Х` и строчные `а е о р с х` → `A B E K M H O P C T X
  a e o p c x`. `У/у` в списке нет намеренно.
- **Решение — по словам.** Слово — кусок между пробелами, переносами, скобками, запятыми, точкой с
  запятой и кавычками. Дефис, точка, `/` и невидимые символы слово не делят: на них держатся коды
  (`XX.0120.10UМА`) и координаты (`8Е+15.45/12N+80.45`).
- **Слово меняется**, если «похоже на код» (есть цифра, есть латинская буква, латинских не меньше
  кириллических, вся кириллица — из списка) **само слово** или **вся ячейка**. Так чинится и код
  посреди русской фразы (`Опора XX.0120.10UМА` → `Опора XX.0120.10UMA`), и английский текст,
  набранный с кириллическими буквами (`Air сompressed 12 bar`).
- **Русское слово** — только кириллица, без латиницы и цифр, и в нём есть строчная буква — не
  меняется никогда: `Насос XX.0120.10UMA` остаётся как есть.
- **Что выделяется после прогона:** слово, где смешаны латиница и кириллица (куски через `/` не
  смешиваются: `кг/kg` — это русский текст); с флажком 5 — буква без латинской пары (`Ж`, `Ш`, `У`…).
  Плюс заголовки таблиц, объединённые области, выделенные не целиком, и ячейки с оформлением
  символов, записанные целиком.
- **Пределы правила:** русское слово ЗАГЛАВНЫМИ рядом с длинным кодом (`ВЕТЕР XX.0120.10UMA`) станет
  `BETEP`; слово, приклеенное к коду без пробела (`Насос-XX.0120.10UMA`, `4-х/Safety`), решается
  целиком; короткий ключ вроде `СЕ.U1` (кириллицы больше, чем латиницы) остаётся — его выделит
  отчёт, и флажок 5 его починит.
- Правило выбрано не на придуманных примерах, а на копиях пяти рабочих книг — около 1,6 млн ячеек с
  кириллицей (см. [CHANGELOG](CHANGELOG.md), версия 3.1). Идея решать по словам — PR #2.

**Какие символы считаются пробельными:**

| Действие | Символы |
|---|---|
| 2. Переносы строк → пробел | `CRLF`, `CR`, `LF`, `U+2028`, `U+2029`, `U+0085`, `U+000B`, `U+000C` |
| 3. Удалить все пробелы | обычный, табуляция, неразрывный `U+00A0`, `U+1680`, `U+2000–200A`, `U+202F`, `U+205F`, `U+3000`; символы нулевой ширины `U+200B–200D`, `U+2060`, `U+FEFF` удаляются |
| 4. Нормализация пробелов | те же символы приводятся к обычному пробелу, повторы схлопываются; нулевой ширины — удаляются |

Края ячейки чистятся всегда: ведущий пробел в ключе — всегда мусор, а глазами его не видно.
Единственное исключение — перенос строки по краю, когда действие 2 выключено: его оставили
намеренно, и макрос его не трогает (соседний пробел всё равно уходит). Прогон без единого флажка
законен и делает ровно это — чистит края.

## Надёжность — как макрос бережёт данные

- **Ничего не пропускает молча.** Обрабатываются все текстовые ячейки выделения, включая скрытые и
  отфильтрованные строки. Всё, что макрос не тронул, посчитано в отчёте; то, на что стоит
  посмотреть, выделено на листе, и выделение проверяется, а не предполагается.
- **Оформление букв сохраняется.** Ячейки с разным оформлением символов правятся посимвольно — для
  текста до 255 символов. Длиннее Excel посимвольно править не даёт: такая ячейка записывается
  целиком, оформление Excel оставляет **по позициям** (оно могло съехать на другие символы), и
  ячейка выделяется.
- **Текст остаётся текстом — и это проверяется.** Запись идёт через формат `@` с возвратом прежнего
  формата, после чего ячейка перечитывается: если в ней оказалось не то или не текст, это ошибка с
  откатом. (Обычное `cell.Value = s` превращает текст в числа, даты и формулы, см. `docs/AUDIT.md`.)
- **Сначала план, потом запись.** Все новые значения вычисляются до первой записи; заблокированная
  ячейка на защищённом листе — отказ до того, как что-то изменилось; ошибка при записи (или
  `Ctrl+Break`) — откат уже записанных ячеек, каждая перечитывается; ячейка с оформлением символов
  возвращается из точной копии. Ошибка **после** последней записи не откатывает ничего (ячейки уже
  проверены), но прибирает за собой и называется в отчёте. `ScreenUpdating`, `EnableEvents`,
  `Calculation`, реакция на `Ctrl+Break` возвращаются на любом пути — и **перечитываются**: что
  вернуть не удалось, написано в отчёте.
- **Адреса ячеек — только в аварии.** Обычный отчёт их не перечисляет (на листе с сотней тысяч
  русских ячеек список был шумом). Исключение одно: если не удался откат ячейки с оформлением
  символов, отчёт называет, какие ячейки вернуть из временной книги.
- **Большие листы.** Отбор через `SpecialCells(xlCellTypeConstants, xlTextValues)`, поэтому целый
  столбец или `Ctrl+A` обрабатываются за секунды, а не перебором миллиона ячеек. Отдельная проба в
  тестах сторожит ловушку `SpecialCells`, который на одиночной ячейке молча расползается на весь лист.
- **Только кнопка «Выполнить» запускает работу** (`Tag = "OK"`); крестик, `Esc` и «Отмена» — отказ.

## Для разработчиков

**Требования и совместимость.** Пользователю нужен только Excel. Python и PowerShell в репозитории —
для разработки: `build.py` собирает `dist/` и надстройку из `src/`, `tests/` гоняют макрос через
Excel, `examples/make_demo.py` сгенерировал демо-книгу. Всё, что они производят, уже лежит в
репозитории готовым. В коде нет `Declare`-вызовов, поэтому подходит и 32-битный Office. Проверено
на Excel 2024 x64, Windows 11 ru-RU. Заявленный минимум — Excel 2016; версии 2010–2013, скорее
всего, тоже работают (лента — формат Office 2010, в коде ничего новее), но не проверялись; Excel
2007 и старше — нет: там `SpecialCells` возвращал неверный результат при более чем 8192 областях
(на 2024 измерено 10 000 областей без ошибок).

**Без надстройки.** Модуль `Cleaning.bas` и форма `CleaningForm.frm` + `CleaningForm.frx` из
[`dist/`](dist/) (в кодировке cp1251, которую ожидает редактор VBA; `src/` — те же тексты в UTF-8
для чтения): `Alt+F11` → `File → Import File…` → оба файла → сохранить → `Alt+F8` → `CleanKeys`.
Подробно — способ 2 в [`docs/INSTALL.md`](docs/INSTALL.md). Программная установка модулей (COM,
PowerShell, требует «Доверять доступ к объектной модели проектов VBA») —
`tools/Install-VbaComponents.ps1`. Инструкция для ИИ-агента, которому прислали архив или надстройку, —
[`docs/INSTALL-FOR-CLAUDE.md`](docs/INSTALL-FOR-CLAUDE.md).

**Точка входа одна — `CleanKeys`.** Второе имя `Замена_Кирилицы_С_Выбором` убрано в 3.0: из-за
него макрос показывался в списке Excel дважды. Если на старое имя была назначена кнопка, её нужно
один раз переназначить. История версий — [`CHANGELOG.md`](CHANGELOG.md), честный разбор работы над
третьей версией — [`docs/AUDIT-v3.md`](docs/AUDIT-v3.md).

### Тесты

В `tests/` — стенд, который прогоняет **настоящий** VBA-код через COM в чистой книге без единого
изменения логики (в копии модуля подменяются две строки: имя модуля и вызов формы, `MsgBox`
перехватывается). 56 входных строк × 8 наборов флажков сверяются с независимой эталонной моделью на
Python, плюс три инварианта по всему набору: с флажком 5 ни в одной ячейке не остаётся омоглифа,
плохого пробела или пробела по краям; с настройками по умолчанию итоговое выделение **ровно** равно
набору подозрительных ячеек, а в тексте отчёта нет ни одного адреса и верны все числа; ни одна
ячейка вне выделения не изменилась. Плюс 45 проб на то, что не выражается строкой (падение пробы
или сломанный инвариант дают `exit 1` — стенд можно ставить в гейт): `#Н/Д` в выделении, `Ctrl+A`,
32 767 символов, защищённый лист, объединённые ячейки, разрывное выделение, скрытая строка,
одиночная ячейка, rich text (в том числе с `CRLF` при любом наборе флажков, табуляцией, на пределе
255 символов), заголовок таблицы Excel, гиперссылка, апостроф-префикс, дата-время, текст `=1 + 1`,
целый столбец с таймером — и **откат по-настоящему**: в тестовую копию модуля внедряется ошибка
записи, после чего проверяется, что всё вернулось, включая оформление rich-ячейки и уже изменённую
объединённую область, — и **путь после записи**: ошибка там не откатывает уже очищенные ячейки, но
закрывает временную книгу, возвращает состояние Excel и называет себя в отчёте, — и **переполнение
отчёта**: когда предупреждений столько, что окно их не вмещает, аварийный блок показывается
отдельным окном первым.

```powershell
python build.py                                          # пересобрать dist/ и надстройку (нужен Excel)
python tests\gen.py dist\Cleaning.bas out --v2
powershell -File tests\Run-CleaningAudit.ps1 -AuditDir out -FormDir dist
python tests\verify.py out            # ожидается: mirror agreement: 448 OK, 0 MISMATCH; invariants: all OK
type out\special.txt                  # исход каждой пробы
python tests\measure_left.py dist     # гейт: тысячи несоседних ячеек, которые надо выделить (exit 1 при сверхлинейном росте)
powershell -File tests\Measure-Speed.ps1 -DistDir dist   # необязательно, ~2 минуты: 8k/20k/40k ячеек
python tests\verify_xlam.py dist --png docs\ribbon.png   # надстройка: код внутри = dist/, лента грузится, снимок ленты
```

Нужны Windows, Excel, Python 3 и включённый доступ к объектной модели VBA. Стенд ничего не
сохраняет и не трогает файлы на диске.
